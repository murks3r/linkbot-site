# Truth check: every claim on the site, what backs it, when it was last checked

Every page that goes live is re-read on the day it goes live against what the product does that day (owner, 2026-10-23), and only then merged to `main` with the owner's go. This list is the tool for that: one row per claim, the fact that backs it, the date it was last checked, and a mark where the sentence depends on work that is not finished (so the go-live check finds it).

The words themselves live in `src/i18n/en.ts` (the source) and the other catalogues; every language says the same thing, so a row covers all five. "Where" names the catalogue key.

**Sources.** `H` = the staging space’s health report (`GET /health` on its Space API, which needs no key; this public file does not name the host), read on 2026-10-26 at 13:30 UTC (contract 0.2.16, build `c065585`, widget `embed.version: 0.5.0-v1`, mail adapter `sink`; before that on 2026-10-25 at 16:36 UTC, contract 0.2.13 and widget 0.3.0-v1). `P` = the Connect lane’s plan, `docs/plan/connect-plan.md` in murks3r/linkbot-connect on `build/vision` at `b5969ac`, read on 2026-10-25: its status line, §1 and §2; and Connect’s `docs/handover/connect.md` on `build/vision` at `64bff6d`, read on 2026-10-26 (staging serves `embed-v0.5.0-v1` since Core-Engine’s CE-M3 on 2026-10-26; Connect’s checks against the served file passed at 03:23 UTC: the wording in five languages, the language fallback, the board’s read-only tests and the watch dry run; E4 with watches on since 2026-10-25, 02:05 UTC; staging’s mail goes to a sink since 2026-10-25, 02:36 UTC).

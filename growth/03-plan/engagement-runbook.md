# Engagement Runbook & Founder Operating Cadence

Low-maintenance procedures so the system survives real weeks. If a routine can't survive a bad week, it's not a routine.

## 1. Daily (15 min, 5 days/week — LinkedIn + inbox)

| Min | Action |
|---|---|
| 2 | Scan notifications; reply to every genuine comment on your posts (same day). |
| 8 | Comment substantively on 3–5 posts by (rotating): DACH recruiting voices, HR/TA leaders, job-search community threads, first-party industry sources. Rule: add a sentence of substance; no "Great post!"; mention Linkbot only if directly asked or directly relevant. |
| 3 | Triage new replies (email/LinkedIn): log in pipeline sheet; route (call / later / no). |
| 2 | Queue check: confirm tomorrow's post is staged (written, reviewed, UTM'd). |

**Never daily:** posting new cold outreach; DMs to strangers; engagement pods; reading vanity metrics.

## 2. Weekly (60 min — Friday)

| Min | Action |
|---|---|
| 25 | Pipeline sheet update: outreaches, replies, calls, pilots, second mandates, case status. Recompute the week's conversion deltas. |
| 15 | Channel numbers: qualified sessions by source, guest-starts, GV, saves, returns (manual counts until D4 analytics lands). |
| 15 | Content queue: schedule next week's 2–3 posts from the drafts; confirm one blog item is progressing; Reddit plan for the week. |
| 5 | Log one "what surprised me" note in the retro log (feeds next week's posts and the W8 review). |

## 3. Monthly (2 h)

- Metrics review against targets (recalibrate provisional numbers).
- Experiment decisions per `09-measurement/experiment-backlog.md` (continue / stop / decide).
- Refresh anything dated: re-check Reddit rules for active communities; skim PH help pages for changes; re-verify one BDU-type market fact if using it in content.
- Update `01-strategy/decisions.md` + `assumptions.md` (death of hypotheses is progress — record it).
- One newsletter issue (if list exists).

## 4. Quarterly (half day)

- Re-verify all platform rules (Reddit × active subs, LinkedIn, PH): update `07-reddit/community-research.md` with new snapshot dates + notes.
- Blog refresh pass: dated facts, benchmark re-run if code moved, "as of" lines updated.
- Prune drafts; archive used assets; update the sources file (`research/sources.md`).
- Re-run the PH readiness gate formally (even if still red).
- Strategy half-page: what converted, what to kill, what to double.

## 5. The publish gate (every external item, no exceptions)

1. Owner reads it out loud. Anything unverifiable, comparative, or boastful gets cut or downgraded to `[Hypothesis]`.
2. Distribution checklist (`02-channels/distribution-checklist.md`) ticked.
3. UTM verified; link resolves; mobile check done.
4. Permissions verified for any name/number/logo.
5. Logged in sign-off table. Then — and only then — it may leave the folder.

## 6. Escalation rules (when things go wrong)

| Situation | Action |
|---|---|
| Negative/hostile reply to outreach or post | One calm factual reply; do not argue; if it's about privacy claims → escalate to owner immediately, pause channel |
| Reddit mod removal or warning | Stop that sub; re-read rules; no appeal arguments; rejoin only with a genuinely compliant contribution plan |
| Press/analyst inquiry | No comment until owner; no numbers beyond published, verifiable ones |
| Someone reports data concern re: Linkbot | Do not improvise; route to privacy contact; capture verbatim |
| A published number turns out wrong | Correct within 48 h visibly ("correction" line), update sources; never silently edit |

## 7. What "low-maintenance" means here

- Maximum 2 push channels per week; if a week breaks, LinkedIn posts → 1, Reddit → 0, everything else already queued.
- Every recurring action has a template or a draft in this folder; creating new formats is a monthly activity, not a weekly improvisation.
- The system's fail-safe is honesty: when in doubt, publish less, disclose more, and record the unknown.

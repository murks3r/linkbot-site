# Iconography

Status: **PROPOSED.** 20 icons, real SVG sources, all generated by `../scripts/gen_assets.py`.

---

## 1. Construction rules

| Rule | Value |
| --- | --- |
| Artboard | `0 0 24 24`, `viewBox` always declared |
| Stroke | `1.5` at 24px (scale the stroke with the icon, do not let it thin) |
| Terminals | `stroke-linecap="round"`, `stroke-linejoin="round"` |
| Fill | `none`, except for a deliberate "solid" node where solidity *means* something |
| Colour | `currentColor` only — an icon never carries its own colour |
| Padding | 3 units, so a 24px box aligns optically with 24px type |
| Text | None. An icon is never a letter or a glyph substitute |
| Accessibility | `role="img"` + `<title>` in the file; decorative instances take `aria-hidden="true"` |
| Dashes | `stroke-dasharray="2.5 2.5"` — used only to mean "not confirmed" or "not known" |

Every file passes the SVG gate in `../scripts/validate_brand.py`: parses, has a `viewBox`, no
script, no image, no remote reference, unique ids.

## 2. The set

The vocabulary follows the product's objects, not a generic UI kit. There is deliberately no
settings gear, no bell, no shopping cart and no rocket.

| Icon | Meaning | Notes |

| `proposed` | Proposed, not confirmed | Dashed frame + hollow core |
| `unresolved-unknown` | UNKNOWN, never rendered as satisfied | Partial ring, dashed remainder, hollow core |
| `authority-grant` | Disclosure authority crossing a boundary | Arrow through a boundary line |
| `authority-revoke` | Future access stops | Same boundary, stopped before the far side |

## 3. Why no padlock, shield, checkmark-badge or fingerprint

**[Fact]** The product has no configured credential adapter, so no claim can currently be
"externally verified", and the product design documents explicitly rejected trust badges. A
padlock icon on a page about permission would assert encryption the release does not provide
(`product-truths.md` C1); a shield or a verification badge would assert verification it cannot
perform (C3). The icon set therefore draws the **mechanism** — a boundary, a grant, a
revocation, a receipt — and never the **assurance**.

## 4. Solid vs hollow is meaningful

Throughout the set, a **solid** node is a real, confirmed participant (the holder, a
counterparty, a granted authority) and a **hollow** node is a party that is described but not
committed (an unresolved requirement, a target, an unknown). This is the icon system's
equivalent of the four-state rule, and it survives greyscale and colour blindness.

## 5. Semantics map to product states

| Product state | Icon | Additional carrier required |
| --- | --- | --- |
| confirmed | `confirmed` | the word "confirmed" |
| proposed | `proposed` | the word "proposed" |
| unknown | `unresolved-unknown` | the word "unknown" |
| denied | `attention` or a text-only negative | the word "denied" |

**An icon is never the only carrier of a state.** Colour plus glyph plus word is the rule in
`../05-colour/colour-system.md` §4.

## 6. Sizing and alignment

| Size | Use | Stroke |
| --- | --- | --- |
| 16px | Inline with 13–14px UI text | 1.5 (do not reduce — it becomes invisible) |
| 20px | Inline with 16px body text | 1.5 |
| 24px | Default, buttons, list rows | 1.5 |
| 32px | Empty states, feature markers | 1.75 |
| 48px+ | Do not enlarge a UI icon; use the mark or the field imagery | — |

At 16px, prefer a text label over an icon. The set is drawn for 24px.

## 7. Adding an icon

1. Name it after the **product object**, not the shape (`authority-grant`, not `arrow-right`).
2. Draw it on the 24 grid with 3-unit padding and a single `1.5` stroke.
3. Add it to the `ICONS` dict in `scripts/gen_assets.py` — never hand-write the file, so the
   whole set stays consistent and regenerable.
4. Re-run `python3 scripts/gen_assets.py && python3 scripts/validate_brand.py`.
5. If it duplicates an existing meaning, do not add it; extend the existing icon's
   documentation instead.
